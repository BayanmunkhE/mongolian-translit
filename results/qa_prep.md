# Асууж магадгүй асуултууд ба хариултууд (хамгаалалт 2026-10-20)

## Өгөгдөл

**1. Синтетик өгөгдлийг яаж үүсгэсэн бэ? Бодит бичлэгтэй хэр төстэй вэ?**
Зөв кирилл текст (Википедиа, FineWeb-2) бүрд санамсаргүй "бичих хэв маяг" оноож латин болгосон: ө→o/u/q, ү→u/v/y, х→h/kh/x, урт эгшиг орхих, цэг таслал хаях, товчлол (bn, shd), 25%-д англи үг оруулах, 10%-д MNS стандарт. Бодит сэтгэгдлийн онцлогийг (EDA) ажиглаад дүрмүүдийг нэмсэн (emoji, сунгасан үсэг, зураасгүй англи дагавар). Бодит шалгалт дээрх зөрүү (синтетик 97% ба бодит 94%) л үлдсэн ялгааг хэмждэг.

**2. 664 сэтгэгдлийг хэн, ямар дүрмээр зассан бэ? Нэг хүний субъектив байдал?**
Би өөрөө, бичсэн нэг дүрмээр: бичсэн хүний санаагаар зөв бичлэг, том үсэг, цэг таслал; англи үг латинаар хэвээр; "шд" → "шүү дээ". Загварын гаралтыг хэзээ ч урьдчилан бөглөөгүй (зөвхөн дүрмийн суурь), тиймээс лавлагаа загвар руу хазайгаагүй. Нэг хүний засвар нь хязгаарлалт: хоёр дахь annotator-ийн зөвшилцлийг (inter-annotator agreement) хэмжээгүй.

**3. Тестийн өгөгдөл сургалтад алдагдсан (leakage) эсэхийг яаж баталгаажуулсан бэ?**
Өгүүлбэрийн хэшээр хуваадаг тул нэг өгүүлбэр хоёр хэсэгт орохгүй; синтетик өгөгдөл үүсгэхдээ бодит тестийн өгүүлбэрийг хасдаг; сургалтын скрипт `real_test` нэртэй файлыг хүлээж авдаггүй; чат тестийн 40 мессежийг ч чат өгөгдлөөс хасдаг. Загварын сонголтыг зөвхөн 178-ийн dev дээр хийсэн.

**4. Чат өгөгдлийг Gemma-гаар үүсгэсэн гэсэн: том загварын гаралт дээр сургах нь зөв үү?**
Gemma зөвхөн кирилл чат мөр (сэдэв, хэллэг) үүсгэсэн, латин талыг нь манай дүрмүүд хийсэн тул "багш загварын" хөрвүүлэлт сургалтад ороогүй. Толь ба дүрмийн шүүлтүүрээр 30%-ийг хассан. Шалгалт нь сургалтад ороогүй 40 бодит чат мессеж.

## Загвар ба сургалт

**5. Яагаад ByT5? mT5, BERT, LSTM биш?**
Оролт нь зөв бичлэггүй, товчилсон латин тул үгийн/дэд үгийн tokenizer задардаг; ByT5 байтаар уншдаг тул ямар ч бичлэгийг ойлгоно. mT5-small-ийг туршихаар төлөвлөсөн ч ByT5 бодит дээр хангалттай байсан. LSTM-ийг таггер хэлбэрт туршсан: шошголох даалгаварт BiLSTM сайн, харин бүтэн өгүүлбэр үүсгэхэд урьдчилан сургасан seq2seq илүү (94% ба 92%).

**6. Хоосноос сургасан загвар яагаад суралцаагүй вэ?**
Seq2seq ByT5 жижиг хувилбар decoder-only "хэлний загвар" болж encoder-оо үл тоодог (loss 1.1-д тогтдог). transformers 5-ын lm_head init алдааг (анхны loss 211) олж зассан ч 6 давхаргатай загвар хуулах даалгаврыг ч сураагүй; 2 давхаргатай жижиг нь сурдаг. Тиймээс урьдчилан сургасан загварыг хайчлах, эсвэл BiLSTM таггер руу шилжсэн.

**7. Яагаад хоосноос сургасан BiLSTM урьдчилан сургасан encoder-ээс сайн гарав?**
Байт бүрийн шошго ойрын хэдхэн байтаас шийдэгддэг локал даалгавар; 1 сая мөр шошготой өгөгдөл хангалттай. Урьдчилан сургалтын давуу тал нь урт хамаарал, бүтэн өгүүлбэр үүсгэх seq2seq-д гардаг. Мөн хайчилсан encoder нь 12-оос 4 давхарга үлдсэн "гэмтсэн" загвар.

**8. Hyperparameter-ууд, сургалтын хугацаа?**
lr 3e-4 AdamW (stage 2–3: 1e-4), batch 16×2, 5% warmup, bf16, early stopping dev CER дээр, beam 4. Нийт GPU цаг ~20 (RTX 4070 SUPER). lr 5e-4, Adafactor, beam 1/8, ByT5-base бүгд статистикийн хувьд тэнцүү.

**9. Загвар хаана алддаг вэ (XAI)?**
Алдааны ангилал: хүний нэр, ховор үг; ө/у, ү/у хоёрдмол үсэг; том жижиг үсэг, цэг таслал; инээдний үг (hha, hhe). Cross-attention зураг нь үсэг тус бүр диагональ хамааралтай, тодорхой байна (`results/xai/`). Үлдсэн алдааны ихэнх нь лавлагааны хэлбэрийн сонголт (суффикс бичлэг) гэж үзэж байна.

## Үнэлгээ

**10. 195 мессеж хангалттай юу? Ялгаа санамсаргүй биш гэдгийг яаж мэдэх вэ?**
Бага. Тиймээс 2000 давталттай paired bootstrap-аар 95% интервал тооцдог: манай загвар ба Gemma-гийн ялгаа −5.9 (−6.9…−4.7), 0-ийг агуулахгүй. Харин v2 ба v3, small ба base зэрэг хэд хэдэн ялгаа 0-ийг агуулсан тул "тэнцүү" гэж тайлагнасан.

**11. CER-ээс гадна ямар хэмжүүр?**
WER, бүтэн зөв (EM 30%), хоёрдмол үсгийн нарийвчлал, англи үг хадгалсан хувь, chrF 89.3, BLEU 69.0; гарын хувьд үгийн нарийвчлал (90%) ба p50/p99 хоцролт; хайлтын хувьд overlap@10.

**12. Gemma-г шударга харьцуулсан уу?**
4-bit шахсан, prompt тусгайлан тохируулаагүй, температур 0, жишээг зөвхөн real_train-аас. Prompt сайжруулбал Gemma дээрдэж болно; ChatGPT/Claude-ийг шалгаагүй (API зардал). Үүнийг слайд дээр ил хэлсэн.

## Утас ба гар

**13. Утсан дээр бодитоор ажиллуулсан уу? Хоцролт?**
Android эмулятор (Pixel 6, API 34) дээр IME суулгаж, бичиж туршсан. Бодит утсан дээр хараахан үгүй (Android утас байхгүй). Десктоп дээр нэг үг 0.3 мс тул утсан дээр 10 мс-ээс бага гэж тооцоолж байна. iOS-ийн 50–70 MB санах ойн хязгаарт 19 MB таггер багтана.

**14. Хэрэглэгчийн сонголтыг яаж ашиглах вэ? Хувийн мэдээлэл?**
Утсан дотор хувийн толинд хадгална; сервер рүү юу ч явахгүй. Вэб демо дээр сонголтыг `/feedback` логт хадгалдаг (зөвшөөрөлтэй), дараагийн сургалтын өгөгдөл болно. Утасны загвар интернэтгүй тул мэдээлэл гадагш гардаггүй.

**15. Контекст (өмнөх үг) хэр чухал вэ?**
ByT5 таггерт 2 өмнөх үг үгийн нарийвчлалыг 84→87% болгосон; BiLSTM таггерт 90% дээр нэмэргүй (локал контекст хангалттай). Толины хувилбаруудыг bigram-аар эрэмбэлдэг (мин/минь).

## Бизнес ба үйл явц

**16. Хэн хэрэглэх вэ, яагаад мөнгө төлөх вэ?**
Хайлт, чатбот, контент модераци хийдэг байгууллага: латин асуулт/сэтгэгдлийг ойлгодог болно. API-тай харьцуулахад 10 сая мессеж/сар дээр сард 2.6 сая төгрөг хэмнэнэ; дотоод сервер нь мэдээлэл гадагш гаргахгүй (банк, төр).

**17. Яагаад энгийн толь/дүрмээр хийж болохгүй вэ?**
Урвуу MNS 5217 стандарт 100 үсэгт 23 алдаа (77%), сайн дүрэм 80%. Хүн бүр өөрөөр бичдэг, "u" у/ү/ө-ийн аль нь болох нь өгүүлбэрийн утгаас хамаардаг.

**18. Дараагийн алхам?**
Бодит утсан дээр туршиж сонголтын өгөгдөл цуглуулах; iOS extension; бодит гараар зассан өгөгдөл нэмэх (хамгийн найдвартай сайжруулалт); cloud дээр байнгын сервер; ChatGPT/Claude-тэй харьцуулалт.

**19. Ямар хүндрэл гарсан, хэрхэн шийдсэн бэ?**
transformers 5-ын API өөрчлөлтөөс warmup чимээгүй алга болсон (олж зассан); fp16-д NaN (bf16/fp32); хоосноос сургалт бүтээгүй (init алдаа + архитектур); int8 шахалт pruned загварыг эвдсэн (lm_head-ийг fp32 үлдээж зассан); ONNX quantizer weights-ийг Constant node тул алгассан (initializer болгож зассан).

**20. Код, repo, CI?**
Git repo, pytest 31 тест (torch-гүй), GitHub Actions workflow; Docker (торчтой ба торчгүй 300 MB ONNX хувилбар); бүх үр дүн PROGRESS.md-д лог хэлбэрээр.
